WHY MONSOON

Why Monsoon

20 things Monsoon does differently

No build in production, arbitrary values without one, a theme from one color, tested contrast and native components. Every reason has a live demo.

01

Zero build in production, from a CDN

One stylesheet link is the whole install: every class is already in the file, 88.4 kB with brotli, so there is no compiler, config or watcher, in development or in production.

 02

Arbitrary values without a build step

Write w-[37px] or bg-[#0ea5e9] when no step fits: a small script writes the rules in the browser, or the purge CLI compiles them for production.

 03

A whole theme from one --seed color

Primary, accent, surfaces, borders, muted text and the focus ring are computed from one OKLCH seed in pure CSS, so one line re-themes everything.

 04

Accessible contrast, tested for every token pair

Every fill and its foreground keep at least 4.5:1 for any seed, in light and dark mode, and the test suite checks each pair across a sweep of seeds.

 05

Per-section theming with style="--seed"

Put a seed on any element and only that subtree re-themes, so a pricing card, a sidebar or a whole tenant can have its own brand on the same page.

 06

Dark mode that follows the nearest themed ancestor

A light card inside a dark section inside a light page is exactly what you expect, at any depth, for the tokens and for the dark: prefix alike.

 07

167 components in the same file

167 components ship in the one stylesheet, 122 of them with no script at all: forms, actions, navigation, overlays and data display.

 08

Components that need no JavaScript

Dialogs, popovers, menus and accordions are built on dialog, the popover attribute and details, so the browser does the work and nothing has to hydrate.

 09

An optional interactive layer

One script adds file drop, cropping, date pickers, sortable lists, comboboxes and more on top of native inputs that keep working without it.

 10

Container query variants built in

Prefix a class with @sm: to @xl: and it reacts to the width of its container, so a card adapts to the column it is dropped into.

 11

Fluid type and spacing utilities

text-fluid-* and p-fluid-* grow smoothly with the viewport between a mobile and a desktop size, with no breakpoint classes and respecting browser zoom.

 12

Print, rtl, ltr and forced-colors variants

Hide navigation when printing, mirror a margin in right to left languages and fix a border for high contrast themes, all with a prefix.

 13

Zero config purge that compiles arbitrary values

One command keeps only the classes your files use and writes static rules for every arbitrary value it finds, with no config file.

 14

Works with any backend or framework

It is plain CSS classes, so server templates, static site generators and single page apps all use it the same way, with 17 step by step install guides.

 15

One shared token scale for every control

Inputs, selects and buttons of the same size share one height, radius and padding token, so a row of mixed controls lines up with no tweaks.

 16

An in-gamut OKLCH palette

Twenty-two hues share one lightness curve and have their chroma capped to sRGB, so step 500 of every hue looks equally strong and renders the same everywhere.

 17

Accessible by default

Every component has a visible focus ring, motion stops under prefers-reduced-motion and controls stay usable in forced colors mode, with no extra classes.

 18

Utilities always override components

Components sit before the utilities in the same file, so a utility on a component always wins without !important or a specificity fight.

 19

One cached file for every page and project

Every page of every site that links the same version shares one file the browser already has, so the second page and the next project load no CSS at all.

 20

A machine readable class index

classes.json lists all 4,923 classes with their CSS and variants, ready for editor completion, linters and other tooling.

FAQ

FAQ

Questions people ask

How do I use utility-first CSS without a build step?

Add one tag, <link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/monsooncss">, and write classes such as px-4, md:grid-cols-3 or hover:bg-primary in your HTML. Every class is already in the file, so there is no compiler, no config file and no watcher to run.

Is a CSS framework from a CDN fine for production?

Yes. The file is cached by the browser after the first visit, and you can pin an exact version such as monsooncss@0.2.0. If you want a smaller file, run npx monsooncss purge once and serve the result yourself.

How do I generate a whole theme from one color in CSS?

Set --seed to any CSS color, for example :root { --seed: #0d9488; }. Monsoon derives primary, secondary, accent, surfaces, muted text, borders and the focus ring from it with OKLCH relative colors, in pure CSS. Put style="--seed: teal" on any element to theme only that section.

How does dark mode work?

It is automatic. Monsoon follows prefers-color-scheme, and you can force a scheme with class="dark", class="light" or data-theme="dark" on the root element or on any section. Semantic colors such as bg-surface and text-foreground switch on their own, so most pages need no dark: classes at all.

Do the components need JavaScript?

No. Dialogs use the native dialog element, menus and popovers use the popover attribute or details, toggles are real checkboxes. Everything is CSS on top of native HTML, so it works in any stack.

Is the color contrast accessible?

The seed formulas push the primary color out of the lightness band where neither white nor dark text is safe, and flip the foreground to match. The test suite checks 4.5:1 (WCAG AA) for every token pair across named seeds and a sweep of sRGB seeds, in light and dark mode.

What is not supported?

Stacked variants on static classes such as dark:hover:bg-muted and the important modifier are not part of a prebuilt stylesheet. Arbitrary values such as w-[37px] work with the optional monsoon.js script or the purge CLI, stacked variants included. For anything else, a style attribute or a few lines of your own CSS next to Monsoon work fine.
