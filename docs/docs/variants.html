Getting started

Variants

A variant is a prefix that applies a utility under a condition: hover:bg-primary/90, md:flex-row, dark:bg-slate-800. Monsoon predeclares 10,237 variant classes, generated for the utility groups where each condition is useful.

5 min read

#How variants work

Write the variant, a colon and the utility. The variant only changes when the rule applies, never what it does:

Because the stylesheet is prebuilt, a variant class exists only where it was generated. hover:bg-primary exists, hover:p-4 does not. The class reference lists the variants of every class, and npx monsooncss classes --filter hover: lists them in a terminal.

#Every variant

focus-visible:the element has keyboard focus:focus-visible
focus-within:the element or a descendant has focus:focus-within

disabled:a form control is disabled:disabled
group-hover:an ancestor with the group class is hovered.group:hover .x
peer-checked:an earlier sibling with the peer class is checked.peer:checked ~ .x
first:, last:the element is the first or last child:first-child, :last-child
odd:, even:the element is an odd or even child:nth-child(odd), :nth-child(even)
motion-safe:the visitor has not asked for reduced motion@media (prefers-reduced-motion: no-preference)

#Group and peer

group-hover: styles a child when an ancestor is hovered. Mark the ancestor with group, and the whole card reacts as one target:

peer-checked: styles an element when an earlier sibling with the peer class is checked. It is how you build reveal panels and custom choices without JavaScript:

The peer must come before the element it controls and share its parent, because CSS can only look at earlier siblings. Keep the input visible or give it a visible focus style, so keyboard users can see where they are.

#What is not supported, and what to do instead

A prebuilt file cannot contain every combination, so a few things are deliberately missing:

Not availableExampleDo this instead
Stacked variantsmd:hover:bg-muted, dark:hover:bg-slate-700Split the conditions across two elements, rely on semantic colors that already adapt to dark mode, or write the rule in CSS.
A variant the class does not havehover:p-4, md:bg-primaryCheck the class reference; otherwise write a small rule.
Opacity modifiers on palette colorsbg-rose-500/50Use a lighter step, or color-mix() with var(--color-rose-500).
The important modifier!p-0Not needed: the reset is in a cascade layer and utilities come last.

Your own CSS can use the theme, so a missing combination takes a few lines and stays correct in every theme and scheme:

Splitting conditions across elements often reads better than a stacked class anyway. Put the breakpoint on a wrapper and the state on the child: <div class="hidden md:block"> around <a class="hover:bg-muted"> gives you a link that only exists from 768px and reacts to hover.

#Print, screen, direction and forced colors

Five more prefixes cover the media and the writing direction a page is shown in. Like the others they are generated only where they are useful, which the table spells out.

PrefixAppliesClassesGenerated for
print:When the page is printed (@media print).677Layout utilities, the same set as the breakpoints: display, position, flex and grid, spacing, sizing and text size.
screen:Only on screens (@media screen).677The same set as print:.
rtl:Inside an element with dir="rtl", or the element itself.494Utilities that name a physical side: left and right margins and padding, positions, rounded corners, borders, translate, space between, flex row and transform origin.
ltr:Inside an element with dir="ltr".494The same set as rtl:.
forced-colors:When a high contrast theme is active (@media (forced-colors: active)).198Display, borders, outlines, underlines, screen reader helpers and forced-color-adjust.

Prefer logical utilities such as ms-4, ps-4 and border-s-2: they follow the writing direction on their own, so rtl: is only needed for the physical ones.

#Frequently asked questions

Why can I not combine two variants like md:hover:?

Every combination would multiply the size of the prebuilt file. Use two elements, semantic colors, or a few lines of CSS with the theme variables.

How do I know if a variant exists for a class?

Search the class reference, which lists the variants of every class, or run npx monsooncss classes --filter with the class name.

Do variants work with component classes?

No. Variants are generated for utilities only. Components handle their own states, such as hover and focus, internally.
